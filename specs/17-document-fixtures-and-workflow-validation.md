# 任务：完整教学材料上传与双 Workflow 联调验收

状态：用户已授权实施；主要流程及三组真实文件联调完成。DOCX版式渲染、uv锁更新及真实DeepSeek调用未完成，见测试报告，不标记全项通过。

## 来源与目标

- 需求来源：用户要求建立有完整正文、可以实际上传的虚构企业测试材料，同时覆盖正常与异常情况，检查材料完整性和 AI 风险预审两个 Workflow。
- 目标用户：演示操作人员、客户经理和风控专员。
- 要解决的问题：现有申请材料只有元数据和教学摘录，无法验证真实文件上传、文本解析、字段核对及风险线索生成。
- 可观察结果：上传完整文档后，两个 Workflow 使用同一申请、同一材料版本及实际提取内容；正常材料通过可自动验证的完整性检查，异常材料明确指出内容缺口或不一致，并可定位原文。
- “真实测试数据”指真实存在、可打开和解析的文件；企业、交易、身份和金额仍为虚构教学数据。

## 当前行为

- 已有材料页、完整性检查接口和报告页风险预审入口。
- `backend/app/main.py` 尚无文件上传接口；`material_workflow_adapter.py` 仅适配元数据及 sample_excerpt。
- `material_workflow_models.py` 的解析状态只有 parsed_mock、failed、not_available；不能把真实上传文件标记成 Mock 解析，也不能把 Mock 标成真实解析。
- 风险预审中的主体和金额比较主要使用离线 fixture；页面没有结构化解析事实，仍提示未评估。
- 任务依据：CC-MAT-001 第二、四、五、六条；CC-POL-002 第二至七条；CC-REV-001 第三至六条。均为虚构教学政策。
- 未确认信息：本机可用 PDF/DOCX 解析及文档渲染依赖需实施时检查；缺依赖如实记录，不能用预设 JSON 假装上传解析结果。

## 期望行为

### 一、完整材料包

本轮先选设备更新贷，使用新设备，避免引入经营收入三个月佐证的额外范围。建立独立测试申请，不覆盖 APP-DEMO-001 至 004 或用户已有复核记录。

| 材料 | 正常组的具体内容 |
| --- | --- |
| 授信申请表 | 虚构主体及一致的教学登记标识、产品、申请金额120000元、用途、联系人、提交日期、教学真实性确认 |
| 主体登记资料 | 同一主体名称和教学登记标识、主体类型、经营范围及经营场所；明确“模拟登记信息，不是真实营业执照”，不仿制印章 |
| 经营情况说明 | 企业业务、场所、主要交易情况、采购设备的业务需求；事实陈述和预测分开 |
| 设备采购计划 | 全新包装设备2台、规格、单价60000元、总价120000元、供应商、采购日期、安装地点与安排、费用和税费口径 |
| 供应商报价单 | 出具方、日期、设备型号/规格、数量、单价和总价、币种、含税口径及运输安装费用说明；与计划一致 |
| 未签约说明 | 采购处于询价阶段、未签约原因、对应报价编号、后续安排；不暗示合同已成立 |

- 六份文件均含有完整正文及表格，可独立阅读；日期和编号相互一致，页码/段落可定位，每页或页眉标明虚构教学用途。
- 交付 DOCX，另导出至少一份可提取文字的 PDF 验证 PDF 解析；PDF 与 DOCX 同内容版本不要求重复上传。
- 教学登记标识显式使用模拟值，不能伪装成已核验的真实统一社会信用代码；系统提示该标识仅用于教学一致性测试。
- 文档模板和生成数据可保留作为维护资料，但 Workflow 不读取预设答案作为解析结果。

### 二、测试组与预期

| 用例 | 输入变化 | 材料完整性预期 | 风险预审预期 |
| --- | --- | --- | --- |
| 正常组 | 上传上述完整六份文件，确认全新设备 | 确定缺项和解析异常为空，必需字段可定位；替代组合充分性仍可待人工确认 | 可核对主体与金额一致，不虚构风险；正常结束或明确人工待核验，绝不输出授信批准 |
| 内容不符合 | 文件名仍为供应商报价单，但正文只有产品介绍，没有出具方、日期、数量和价格 | 文件可读取，但缺关键报价字段，不能因文件名合格而通过 | 采购价格依据不足，要求补充符合要求的报价单或合同 |
| 数值不一致 | 计划与申请均120000元，报价同口径总价150000元，其余字段完整 | 可通过结构字段完整性检查，不把差异混作缺文件 | 输出双方金额和位置，要求解释差异；不自动调整额度或认定违规 |
| 文件异常 | 上传一份非允许格式或损坏文件 | 非允许格式拒绝；损坏文件明确不可读取，不能形成空正文成功记录 | 只要记录了失败材料，就提示不可用；不能用历史正常版本充当新证据 |

至少交付正常组和内容不符合组的完整文档；其他组复用公共材料并提供替换文件及独立操作说明。每组使用独立申请，或明确递增版本，不混淆测试结果。

### 三、上传、解析与事实来源

- 材料页增加真实文件选择和上传入口，绑定当前申请和材料类型，服务端生成材料编号、版本及安全存储名；支持下载原文件。
- 文件存于 Git 忽略的本地数据目录，上传记录与解析结果持久化；仓库内交付的教学文档样例单独保存。重启后记录可读取。
- 支持本轮 DOCX 正文/表格及文字型 PDF；扫描件无可提取文字时提示需 OCR 或人工处理，本轮不实现 OCR。
- 校验允许格式、实际可解析性、文件大小及安全文件名。大小限制是工程限制，页面明确说明，不宣称政策限制。避免路径穿越与归档解压资源耗尽。
- 提取全文、页码（PDF）或段落/表格单元格（DOCX）；保存实际文件摘要、解析器版本和失败原因。不伪造 DOCX 页码。
- 使用明确字段标签/表格结构提取本轮材料字段。未识别、未检查、值缺失分别记录；未知格式转人工，不声称支持任意版式。
- 材料名称只作为声明类别，不能证明正文属于该类材料。模型候选也不能自动满足必交要求。
- 两个 Workflow 必须消费同一真实解析结果；风险核对输入来自可追溯的实际字段，不是 CLI fixture 注入。
- 输入未知时保留未知。设备新旧属性须从明确正文证据或人工声明获得，不能默认新设备。

### 四、状态与人工边界

- 材料完整性“通过”只表示当前自动检查覆盖的提交、可读性和必需字段满足要求，替代组合充分性与原件真实性仍由人工核验。
- 风险预审 completed 只表示节点正常执行，不等于无风险或批准。信息足够时不能永远硬编码 insufficient_evidence；存在缺口时也不能为了正常用例通过而清空缺口。
- 对名称不同、金额差异或无法核实用途，只给线索、证据和复核事项，不认定欺诈、不作授信通过/拒绝决定。
- 上传和重新预审不覆盖历史证据，不自动改变申请状态或人工复核记录。
- 保持旧材料、旧接口和历史 Mock 报告兼容。新增真实解析来源必须同步模型、契约、两个 Workflow 及测试。

## 验收

1. 文档人工打开及渲染检查：正文完整、表格无遮挡、教学标识明确；正常组内容互相一致。
2. 浏览器逐一上传正常组，确认持久化、版本、可下载原件和真实解析内容；重启后仍可读。
3. 正常组完整性确定缺项/异常为空，风险预审有实际证据，不再仅因历史适配器缺解析数据而永远提示未评估。
4. 内容不符合组：文件名正确也不能满足内容核验；两个 Workflow 均指出报价关键事实不足。
5. 数值差异组：材料结构完整但风险预审定位120000元与150000元，展示人工复核事项。
6. 无效格式/损坏文件：明确错误或不可读状态，不形成虚假的解析成功；失败新版不回退旧版。
7. 申请隔离、重复文件/版本、非法文件名、上传大小限制和解析异常有自动测试。
8. 实测正常/异常两组的页面截图、原文证据和两个 Workflow JSON 输出，记录实际预期对照和问题清单。
9. DeepSeek 成功/失败与规则结果分别验收；未实际调用时注明，不伪称AI效果已验证。正文引文必须来自实际上传文件。
10. 根目录运行 `python scripts/check_project.py` 并记录真实结果；新脚本命令在实施完成后写入使用说明。

交付：完整教学材料包、上传/解析功能、两条流程的运行证据、测试与问题记录。文件数量不是完成依据，以真实文件内容贯通两个 Workflow 为准。
