# 任务：AI 风险预审 Workflow

状态：用户已完成本轮验收；按当前材料不足场景通过，完整内容材料的效果验证和测试材料后续补充。

## 本轮验收结论

- 用户实测反馈：申请材料只有名称，没有可用内容；材料完整性检查未通过，AI 预审指出缺失项，没有擅自给出审核通过结论，符合预期。
- 本轮以“证据不足时正确提示缺口、不自动下授信结论”的流程行为作为验收范围，用户确认通过。
- 此反馈不等同于有内容材料的风险识别准确率验证，也不据此确认实际调用了模型或模型状态为 completed。
- 完整的材料正文样例、AI 分析效果及其余未覆盖的测试证据由后续任务补充；不将其记为已测试通过。

## 来源与目标

- 需求来源：F3 实战任务，基于申请信息、材料和政策规则输出风险提示及人工复核事项；至少展示一项系统不应自动下结论的判断。
- 目标用户：风控专员；客户经理可查看线索、跟进补件。
- 要解决的问题：材料完整性检查只能说明提交情况和内容缺口；已有报告为 Mock，尚不能按当前申请运行风险预审。
- 可观察结果：进入单笔申请的 AI 预审报告页，点击运行，看到有证据、有政策出处的结构化风险提示、缺失信息、人工复核事项和节点执行记录；模型失败也能看到已完成的规则结果及失败说明。
- 沿用“先跑通流程”的目标，不以本轮实现宣称风险识别准确率达标。

## 当前行为

- 入口：申请详情 → AI 预审报告；直接地址 `?application=APP-DEMO-003&view=report`。
- `frontend/src/ReportPage.jsx` 展示 `detail.reports` 中的既有报告；现有 `Report`、`ReportItem` 和复核记录有关联，不能直接替换其语义。
- `POST /api/applications/{application_id}/materials/check` 已从服务端读取材料，执行完整性 Workflow，返回缺项、异常、待确认及节点轨迹，不保存运行结果或改变状态。
- 材料适配见 `backend/app/material_workflow_adapter.py`；`legacy_metadata` 只有元数据和教学摘录，不代表全文解析；`mock_parsed` 是独立虚构测试输入。
- 申请模型目前没有可直接比较的月收入、币种、统计期间、设备预算等完整字段；不能从申请金额或企业名称推算。

- 已有 Chroma/BGE-M3、可选 reranker、DeepSeek 客户端可复用；本轮不改政策问答的会话记忆或提示词。
- 待验证：现有演示材料能够支持多少语义判断、真实 DeepSeek 输出稳定性。均需实测，不能把 Mock 测试等同于实际效果验证。

## 期望行为

### 1. 输入与证据边界

- 按同一 `application_id` 获取企业、申请、最新材料版本，内部运行完整性检查，避免依赖用户先在材料页点过按钮。
- API 仅接收运行选项、与上一轮相同的人工演示条件声明；禁止客户端替换申请、材料、解析结果或政策。
- 每份证据记录类型、申请编号、材料编号/版本（若有）、字段路径或段落位置、原文及来源模式。申请字段和材料原文分别标识。
- 教学摘录可供模型提出有限线索，必须显示“仅基于教学摘录，未核验全文”；解析失败材料不作为可读正文发送给模型；缺失材料不伪造原文证据。
- 测试 fixture 可提供收入、期间、预算等结构化事实，须明确 `fixture` 来源和字段位置；本轮不擅自扩充正式申请对象，不把测试事实带入页面申请。
- 沿用最新版本选择策略；不得用旧版内容填补新版解析失败。保留版本快照和输入摘要，便于核对本次运行范围。

### 2. Workflow 节点与分支

配置文件明确节点、依赖顺序、允许分支和终止路径；加载时验证，运行时记录真实分支，不只列出固定步骤名称。

| 节点 | 实现责任 | 输出与异常分支 |
| --- | --- | --- |
| 输入校验与快照 | 代码 | 同申请关联、产品、材料版本、输入模式；不存在申请返回 404，非法选项返回 422 |
| 材料完整性检查 | 复用上一轮规则引擎 | 缺项/异常/条件待确认；材料为空则跳过正文语义分析，仍汇总缺项 |
| 政策准备 | 硬规则引用 + 产品限定检索 | 确定规则直接绑定条款；语义辅助使用现有向量 Top-K=8 和上下文配置，通用条款及当前产品条款均可用 |
| 确定性核对 | 代码和规则配置 | 执行有明确输入的规则；缺输入/口径不明输出未评估，不猜测 |
| AI 辅助分析 | DeepSeek，用户显式开启 | 仅使用提供的可读证据和适用政策，提出关联/差异线索及复核问题；不执行状态动作 |
| 输出校验与合并 | 代码 | 验证结构、引用、产品范围和输出边界；合并重复问题，规则结果不能被模型删除或改写 |
| 汇总展示 | 代码 | `risk_items`、`missing_info`、`human_review_items`、`need_human_review` 和 `node_trace` |

- Chroma 不可用：保留本地有效规则及其条款，明确标注检索降级；跳过依赖检索的模型分析，不声称已覆盖全部政策。
- 产品未知、配置无效或引用条款版本不一致：停止受影响判断，不跨产品套用；无有效规则配置时返回 503。
- 模型关闭：提供规则结果并标注 AI 未执行。模型超时、缺配置、格式错误或引用校验失败：丢弃无效模型结果，保留规则结果，状态为 `degraded`，允许重试。
- 材料为空、不可读或资料不足：状态为 `insufficient_evidence`；若同时模型失败，以 `degraded` 为运行状态，另保留全部证据不足事项。
- `completed` 仅表示约定节点执行完成，不表示申请通过或无风险；每条结果均需人工复核。

### 3. 风险分类与判断依据

以下分类是本项目的线索分类，不是信用评级；不生成高/中/低信用风险分或违约概率。

| 类别 | 判定逻辑与责任 | 政策出处（均为 1.0） |
| --- | --- | --- |
| 材料与证据缺口 | 规则复用缺项、解析失败、字段未核验；已提交和证据充分分别表达 | CC-MAT-001 第二至四条；CC-REV-001 第三、五、六条 |
| 主体对应待核实 | 明确结构化字段可做规范化后差异比对；简称/曾用名关系由模型提示、人工确认，不能认定欺诈 | CC-POL-001 第三条；CC-REV-001 第二、五条 |
| 数值或统计口径待核对 | 只有数值、币种、单位、期间及含税口径均明确且可比才计算差异；否则列缺失口径。收入与账户总入账不能等同 | CC-POL-001 第六、七条；CC-POL-002 第六条 |
| 收入期间待核对 | 依申请提交日期计算前三个完整自然月；经营不足三个月需开始经营日期和说明，条件不明先核实 | CC-POL-001 第五条 |
| 用途与产品范围待核实 | 模型依据原文提示用途与产品/经营活动可能不对应；明确政策限制可引用，但真实用途与最终适用性由人工核验，不靠关键词自动拒绝 | CC-POL-001 第一、二、八条；CC-POL-002 第一、二条 |
| 材料版本需复核 | 记录使用版本及历史报告未覆盖的新材料；时间变化只触发核对，不自动认定实质变更 | CC-POL-002 第八条；CC-REV-001 第七条 |

规则配置包含规则 ID、产品范围、输入前提、有限的检查类型、政策文号/版本/条号、缺输入时的处理和人工操作建议；不执行配置中的任意代码，不添加政策未规定的比例阈值或准入条件。

### 4. 系统不应自动下结论的案例

**案例：申请名称与登记资料名称不同。**

系统可输出“主体名称存在差异，需确认简称、历史名称或变更关系”，列出两处原文、材料版本和 CC-POL-001 第三条，并请风控专员核验变更记录。系统不能输出“冒用主体”“企业欺诈”或“拒绝授信”；名称不同可能存在合法解释，模型无法确认原件真实性。

另一边界：设备申请金额与预算不同，只记录差异并要求解释用途或资金构成；CC-POL-002 第六条未规定贷款成数和容忍阈值，不能自动调额度或认定违规。

### 5. 结构化输出及校验

沿用项目 Python/API 的 snake_case；对应任务示例的 riskItems/evidence/missingInfo/needHumanReview。

| 字段 | 约定 |
| --- | --- |
| `run_id` / `application_id` / `generated_at` | 本次独立运行标识、所属申请、时间 |
| `workflow_version` / `rule_version` / `input_snapshot` | 规则及输入版本追溯，不含密钥 |
| `run_status` / `model_status` / `retrieval_status` | 执行完成、降级、证据不足；明确组件是否执行 |
| `risk_items` | 每项含 `item_id`、`category`、`title`、`description`、`origin`（rule/model）、`rule_id`（适用时）、`evidence`、`policy_refs`、`suggested_human_action` |
| `missing_info` | 缺少或未核验的信息、原因、来源位置、建议补充内容；区分缺失和未检查 |
| `human_review_items` | 人工应核对的问题、关联线索 ID、证据位置和下一步动作；不是自动写入的复核结论 |
| `need_human_review` | 所有成功返回的教学预审结果均为 true，即使风险列表为空 |
| `limitations` / `node_trace` | 教学摘录、未解析、未覆盖范围和各节点状态/耗时/分支 |

- 材料 ID、版本必须属于本次申请快照；原文必须在该来源中真实存在；政策引用必须来自本次允许的产品及版本。
- 模型只能引用分配好的证据 ID 和条款 ID，后端解析为真实内容；伪造 ID、跨申请证据、无对应原文均不作为有效输出。
- 无证据支持的推断不能作为事实线索；可按明确缺口形成待核实问题。原文引用校验并不保证逻辑正确，仍须人工阅读。
- 严格结构拒绝额外的审批结论/额度/利率/信用评分字段；自然语言包含自动通过、拒绝或欺诈定性等禁止结论时，拒绝该模型响应并显示降级原因。材料内“忽略规则”等内容只作为不可信资料，不作为执行指令。
- 缺材料项允许材料 `evidence` 为空，但必须记录已检查的材料列表范围和规则依据；空证据不能伪装成已核实。

- 新增 `POST /api/applications/{application_id}/risk-precheck`。默认纯规则；页面可显式开启 AI 辅助，并说明会调用外部 DeepSeek 服务。测试默认注入假客户端，禁止自动付费调用。
- **前端入口必须清楚**：申请详情已有“AI 预审报告”导航保留，在报告页顶部新增“运行风险预审”区域；即使原来没有报告也显示入口。材料页增加进入本申请报告页的按钮。
- 展示运行中、错误重试、规则/模型状态、分类线索、缺失信息、原文依据和节点记录；切换申请取消旧请求，旧结果不得覆盖新申请。
- 本次结果与历史 Mock 报告分区显示，明确“本次运行结果，尚未纳入原有逐项复核记录”；页面提供查看材料和进入既有人工复核的导航。
- 本轮不把新结果写入原有 `reports`，不改变现有 `review.report_id` 与 `item_reviews` 的关联，不把新线索伪装成已进入逐项确认流程。新 Workflow 结果的持久化及正式纳入逐项复核另立任务。
- API 本轮返回临时结果，刷新后需重新运行；CLI 支持将虚构输入和输出保存为交付证据。运行不修改申请状态、既有报告、人工复核记录及风险看板统计。
- 使用普通请求响应，暂不增加 SSE 或后台任务；模型调用须有超时，失败按上述约定返回，不能无限等待。

| 用例 | 操作与预期结果 |
| --- | --- |
| 1 正常流程 | 用明确标注的完整虚构输入运行，返回结构化结果及完整节点轨迹；不输出授信决定 |
| 2 材料为空 | 缺项可见，正文模型节点跳过，不把空结果视为无风险 |
