# 任务：纯向量检索 Top-K 小规模测试

## 来源与目标

- 来源：用户要求通过一轮测试确定合理 K，暂不使用混合检索。
- 目标：比较 K=1、3、5、8、10、15、20，记录逐题结果，选出覆盖已标注依据的最小 K。
- 这是教学开发集上的经验选择，不保证未知问题的最高召回率。

## 当前行为

- `scripts/knowledge_base.py query` 每次仅查询一个问题，尚无批量指标。
- `management/03-检索验收用例.md` 已有 Q01—Q15 的文档级依据。
- 用户报告本机入库及检索成功；Agent 当前运行后端环境遇到 NumPy DLL 拒绝访问。

## 期望行为

- 测试集在 management 中保存，绝不导入 corpus。
- 按当前 1.0 版本条款核对标签、产品和版本；无依据题不计正例召回。
- 每题召回最大 K，再以同一排名前缀比较各 K，避免重复编码；记录候选、距离及漏召回条款。
- 宏平均 Recall@K=每题命中标注条款数/标注条款数的平均。
- 全依据覆盖率=找齐全部标注条款的正例问题占比；同时报告 Hit@K。
- 仅当开发集 Recall 和全依据覆盖均达到 100% 时，建议满足条件的最小候选 K；否则列出漏召回，不强行选值。
- 条款标签是待人工确认的参考集合，并非穷尽所有相关条款；本轮不计算误导性的 Precision。

## 本轮范围

- 允许：本任务卡、AGENTS.md 指针、README、评测脚本、管理目录的测试集/说明、相关单元测试。
- 生成产物：`backend/.data/knowledge-base/top-k-evaluation/`。
- 暂不：修改默认 K、Reranker、LLM、页面、混合检索、模型下载或环境重装。
- 保持：原正文、索引及业务状态不变；沿用产品过滤和活动索引校验。

## 验收

- 手算样例验证 Recall、Hit、全依据覆盖和最小 K 选择；空结果、负例、错误标签均测试。
- 运行 `python scripts/check_project.py`；后端环境执行 `scripts/evaluate_retrieval.py`。
- 输出逐题 JSON 与 Markdown 汇总，记录语料、模型及测试集指纹；失败不输出成功评测报告。
