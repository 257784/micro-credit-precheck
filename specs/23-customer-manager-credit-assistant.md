# 任务：客户经理授信助手与只读 Agent Harness

实施状态：只读助手、服务端教学权限、审计及界面已接入；隔离测试和独立MySQL样例验证通过。真实DeepSeek最小调用遇到network_error，未完成真实模型验收；浏览器断网/取消及真实多用户并发等尚未完整覆盖，见docs/architecture/23-客户经理授信助手验证.md。

## 来源与目标

- 需求来源：用户希望在既有申请管理、政策问答和两条 Workflow 之上增加能够自主选择工具的客户经理助手，以自然语言完成跨页面的信息查找和结果整理。
- 目标用户：使用虚构教学申请的客户经理；风控人员继续在原有页面进行人工复核。
- 要解决的问题：用户不知道需要查哪些页面或先执行哪个检查时，需要自行组合申请、材料、风险线索与政策依据。
- 可观察结果：输入申请相关问题后，助手按需调用只读工具、必要时追问，并展示工具轨迹、事实依据、缺口及人工核对事项。
- 此阶段是离线教学原型，Agent 不代表风控人员，不输出最终授信、审批或放款决定。

## 当前行为与已知限制

- 用户可通过申请详情、材料页和报告页分别查询；`backend/app/services/prechecks.py`将材料检查与风险预审封装为共享业务入口。
- `backend/app/tools/registry.py`有两项只读工具及 Pydantic 参数校验，但尚无可信用户上下文、申请访问范围控制、Agent 循环或完整审计；不能仅凭现有白名单宣称具备权限控制。
- `backend/app/api/reviews.py`依赖 `x_demo_role`，是可由客户端伪造的教学演示角色，并非真实认证。现有对话存储为单进程内存，非持久或跨进程会话。
- `backend/app/llm/streaming.py`现有接口处理文本 JSON 流，尚未实现 tool_calls 参数及流式片段拼接；不应假设能直接处理工具调用。
- 政策问答/RAG 原配置仍缺失；两条 Workflow 的 Python 规则是按现存教学资料重建的版本，不能声称与已删除配置完全一致。本轮必须展示政策检索不可用的降级，不得为通过测试伪造政策结果。
- 数据库已有 APP-FICT-001 至 010 及虚构 DOCX；这些记录不是并发、权限或真实客户数据的代表性样本。

## 期望行为

### 用户体验与对话

- 提供单独的“客户经理授信助手”对话入口；可从申请详情携带 application_id 进入，也可在对话中输入 ID。上下文申请仅是线索，不能作为授权证明。
- 多轮会话可记住当前已授权申请 ID、用户已明确提供且标记来源的条件、待澄清问题和有限的近期消息；切换申请时清除申请特有条件，避免跨申请串用。用户未提供 ID 时追问，不自行选择申请。
- 遇到条件性材料所需事实未知时，提示并追问，不能将模型推测当作人工确认。已确认事实需保留来源、消息关联，改变条件后重新运行相关工具。
- 同一个会话同一时间最多运行一轮；使用客户端 request_id 去重，成功轮次重复请求返回已有结果；中断或失败使用新 request_id 并记录关联，不重复将未完成回答写入历史。
- 以 SSE 展示可读进度、工具开始/结束、回答片段、最终结果和错误；展示工具名称、状态、耗时和可公开的依据，不输出模型隐藏推理、密钥或原始完整材料。断线、取消、超时或流中断不得标记成功，客户端可重试。
- 最终内容区分申请事实、工具发现、政策依据、待确认事项；引用必须可映射到本轮工具返回的申请/材料 ID、版本和位置或政策文号、版本、条款。校验失败时丢弃不受支持的结论并提示证据不足，不输出无依据的结论。
- 为避免流式输出未经校验的事实，先流式显示执行进度；正文仅在结构及引用校验后分段发送，或采用可撤回草稿并在失败时明确回滚。完成事件仅在最终校验及审计成功后发送。

### 工具与 Service

- 模型仅能选择已注册的、版本化的只读工具；工具封装调用 Service，不复制 Workflow 或直接运行 SQL。明确四类能力：

| 工具 | 必需输入 | 行为 |
| --- | --- | --- |
| `get_application` | application_id | 返回授权范围内的申请摘要与状态；不存在或无权不泄露跨用户信息 |
| `list_materials` | application_id | 返回同一申请材料类别、版本、解析状态、受控引用；不默认返回完整原件 |
| `check_materials` | application_id、可信来源的已知条件 | 调用既有材料完整性 Service，输出缺失、异常及待确认 |
| `run_risk_precheck` | application_id、可信来源的已知条件 | 调用风险预审 Service，默认 `use_model=false`，保留不足及人工复核标志 |
| `search_policy` | 问题和可选产品范围 | 若政策检索依赖可用才调用现有检索服务；否则返回 `dependency_unavailable`，不得编造来源 |

- `search_policy` 为受控只读工具，能否使用由运行时依赖检查决定；不在本轮偷偷重建或更改知识库配置与索引。材料/风险工具不允许模型自行启用二次外部模型调用，除非未来另有明确需求和授权。
- 工具名称使用服务端白名单；每项参数采用独立 Pydantic Schema，拒绝额外字段、异常长度和非法条件来源；工具结果提供稳定的 status、证据和 run_id。模型只能提交业务参数，不能指定 user_id、角色、权限或跨会话上下文。
- 模型输出只是调用请求，执行器逐项检查调用 ID、名称、参数、权限和预算后才执行；将工具结果回传模型供下一轮选择。未知工具或错误参数不触发底层 Service；受限重试后明确失败。
- 不向模型暴露数据库连接、任意 SQL、Shell、文件系统、上传、修改、审批或转账等工具。`Service` 必须保留原有业务校验；只在 HTTP 路由存在、工具调用可能绕过的必要安全校验，应移至共享授权/服务入口，HTTP 与 Agent 共同调用，不改变既有 API 行为。

### Harness、权限和审计

- 建立可信 `RequestContext`（actor、教学角色、可访问申请范围、会话/请求 ID），在服务端创建和注入；不从 LLM 输出、普通请求体或工具参数接收身份。会话与主体绑定，每次读取会话和每次执行工具都重新授权。
- 本轮仅使用服务端配置或明确限定的演示账号映射，不能把任意客户端传入的 `x_demo_role` 或用户声明当作可信身份；必须明确标注演示模式、仅虚构数据、非生产认证。默认拒绝不在授权范围内的申请；服务端管理的演示范围与10笔数据匹配，测试额外构造两个互不相同的主体及申请范围。实际生产登录、组织隔离与 RBAC 系统暂不实现。
- 会话 ID 不作为凭证。跨主体查看、续写、取消另一会话必须被拒绝；未知申请与无权访问对外采用相同的不可访问响应，审计内部保留可区分的拒绝原因码且不泄露不存在/无权细节。
- 独立工具执行器集中处理白名单、Schema、授权、错误、调用次数和结果裁剪。单轮最多 8 次工具调用、最多 6 次模型请求、60 秒总时限及 2 次同类可恢复错误；限制为教学初始值，记录触发原因，不允许无限循环。一次模型输出包含多个调用时逐个授权、计入预算；超限调用不得执行。
- 对话和工具外部内容、材料正文、检索条款均视为不可信数据，不能通过指令改变系统规则、身份或工具白名单。回答应保留“未核验/待人工”的语义；无依据不能写“无风险”或最终授信结论。
- 新建持久化审计记录（独立数据库表，通过显式版本迁移或初始化脚本创建；不得依赖 `create_all` 修改已有表），至少记录事件 ID、UTC 时间、run_id、conversation_id、request_id、服务端 actor、工具名、目标申请 ID、结果状态、拒绝/失败原因码、耗时与关联 tool_call_id。日志及记录不得包含密钥、完整材料正文或模型隐藏推理。迁移需幂等、保留已有业务数据，失败不得自动清库。
- 每个工具调用在执行前写入受控的审计意图，随后记录执行结果或失败；审计不可写时拒绝执行并提示系统不可用，不能静默执行。拒绝、参数错误、取消、超时、异常同样有结果记录；不持有数据库事务等待模型或其他长时间任务。对进程崩溃后未完成的意图可标记为未知，禁止推断已成功。
- 服务端日志与审计表分工明确：日志用于故障排查，审计用于追踪；本轮需提供服务端按主体、申请 ID、时间或 run_id 查询的受控方式及权限校验，默认仅演示管理员可读。不得把审计查询能力暴露给模型。

### DeepSeek、错误与流

- 复用现有环境变量与密钥管理，增加支持 tools 和多轮 tool_calls 的模型适配器；符合 DeepSeek 的工具调用消息关联格式，不记录凭据。
- 模型的工具参数若以流式增量到达，按 tool_call_id/index 完整拼接并等待结束后再解析和执行；参数过大、非法 JSON、不完整流一律不得执行。也可在工具决策轮采用非流式请求，最终输出仍使用 SSE，但必须说明实际方式与延迟。
- 认证失败、模型超时、限流、工具异常、政策检索不可用均有可识别的状态及重试提示；保留已完成的可用工具结果，不把失败的组件显示为成功。工具拒绝不向模型暴露敏感数据库异常。
- 用户取消时停止后续模型和工具调用；已经开始的只读同步工具可能无法立即中断，需记录实际结束或未知状态，不虚构取消成功。错误响应不暴露连接 URL、密钥或内部堆栈。

## 验收

使用可注入的假模型和隔离测试数据库，至少覆盖以下情形，验证工具调用顺序及返回证据而非只看 HTTP 200：

1. 一条自然语言请求调用申请查询、材料检查并返回有申请 ID 的结果；另一条只问状态时不强制运行所有 Workflow。
2. 未提供申请 ID 或条件时追问；用户补充后继续；切换申请不得沿用上一个申请的条件。
3. 未知工具、额外字段、无效 JSON、分片不完整/超长参数被拒绝，Service 未执行。
4. 未授权申请、跨会话读取/取消、伪造角色或模型参数伪造主体均被拒绝；授权申请正常工作；拒绝事件可审计。
5. 材料缺失、解析失败、金额差异分别保留实际证据及人工复核提示；不得声称无风险或自动审批。
6. RAG 配置缺失、模型超时或工具报错时，显示受影响组件及已获得的信息，不伪造政策依据；模型调用关闭时不产生付费请求。
7. 用户取消、并发重复请求、重复 request_id、工具与模型调用超限、审计写入失败、服务重启后的会话状态均按设计处理；审计失败时工具不能执行。
8. 含恶意指令的材料或工具结果不能改变身份、规则或工具范围；对不存在的引用与禁止结论进行拒绝或降级。
9. 审计记录能关联 actor、会话、申请、工具和结果；验证不包含密钥或全文；演示非管理员不能查看其他用户审计。
10. 对 APP-FICT 10 笔样例执行至少正常、缺失、解析失败、金额差异四种只读助手场景，确认运行前后业务状态和复核记录未变化。若样例对权限隔离不足，在隔离测试库额外构造测试数据，不改变开发库。
11. 前端验证加载、流式进度、追问、工具轨迹、完成、错误、取消与切换申请；无数据与 404/403 状态清晰可见。
12. 在隔离环境验证审计表迁移可重复运行且不覆盖业务记录。真实 DeepSeek 调用为显式单独步骤，记录是否执行、成本和结果；没有真实模型验证时不得写成通过。

- 命令：根目录 `python scripts/check_project.py` 当前仅执行空白、语法和前端构建；本轮需新增可执行的隔离 Harness 验证命令，并在实施后将实际命令、结果写入交付报告。真实 MySQL 验证若无法执行，明确标记未通过或未运行。
- 交付：代码 Diff、接口/工具契约、迁移与回退说明、隔离测试输出、前端证据、真实模型是否调用、未完成项及已知风险。
