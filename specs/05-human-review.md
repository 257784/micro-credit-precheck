# 任务：人工复核页（核心链路第 5 页）

## 来源与目标

- 需求来源：`../../06-F2-MVP范围表.md` 和 `../../06-F2交接清单.md` 的复核、角色与状态流转要求。
- 目标用户：风控专员提交复核；客户经理只读查看。
- 要解决的问题：目前无法开始复核、保存意见、要求补件或回看记录。
- 完成后的可观察结果：同一申请从待风控复核进入风控复核中，再由风控专员提交到待审批或待企业补充材料；记录可在重启后回看。

## 当前行为

- 触发步骤：从详情或报告查看申请。
- 实际结果：只有只读报告，无复核输入、写入接口或记录。
- 相关文件/接口：`backend/app/main.py`、`backend/app/data.py`、`backend/app/models.py`、`frontend/src/App.jsx`。
- 未确认信息：真实身份与审批权限未接入；本轮使用明确标记的教学角色切换和本地 SQLite 持久化。

## 期望行为

- 正常输入 → 风控专员先开始复核，再逐项确认或修正关注项、填写意见并提交；完成复核到待审批，要求补件到待企业补充材料。
- 信息不足 → 无报告或解析失败时不能直接完成复核，可写明原因要求补件；缺少意见或关注项处理不能提交。
- 错误/冲突 → 客户经理写入返回 403；过期状态或重复提交返回 409；接口错误保留输入并提示重试。
- 人工确认点 → 风控专员明确选择复核结果，系统不自动给出审批结论。

## 本轮范围

- 允许修改：复核页、路由及角色演示、复核模型/接口/本地存储、状态与记录读取、测试及其运行入口、契约与运行说明。
- 暂不实现：生产登录、MySQL、正式授信审批、补交上传后的重新初检。
- 必须保持：申请 ID 关联、现有种子数据和报告只读、客户经理不可提交、重启后记录可回看。

## 验收

- 用例1：`APP-DEMO-001` 开始复核、确认关注项、写意见、完成复核后状态为待审批，记录和进度可回看。
- 用例2：`APP-DEMO-003` 解析失败时要求补件后状态为待企业补充材料；无权、重复提交及无报告完成请求被拒绝。
- 测试命令：`python scripts/check_project.py`、`git diff --check`。
- 交付证据：代码 Diff、测试输出、未通过项及原因。
