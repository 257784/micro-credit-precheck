# 任务：身份认证、进件补件与 Agent 数据隔离

> 实施进度：本地账号、业务接口与两类 Agent 会话、企业材料上传与初检后重新提交、管理员历史归属绑定和审计查询已接入。隔离 SQLite 多用户及材料验证通过，MySQL 并发认领已通过；风险报告持久化由第29轮接入，真实模型多用户联调仍未完成，不作为生产安全验收。

## 来源与目标

- 来源：本轮用户要求企业上传材料、补件重新提交、客户经理分配，并让两个 Agent 使用真实身份及数据隔离。
- 目标用户：企业客户、客户经理、风控专员及授权分配人员。
- 目标：从登录、申请、材料上传、补件、分配到 Agent 使用形成可校验的业务链，阻止跨主体访问。

## 当前行为

- 企业表单保存申请，但角色由客户端请求头自报；企业材料上传、重新提交和客户经理分配缺失。
- 材料与申请读取接口缺少统一的身份及归属验证，现有会话与工具部分使用固定演示身份。
- 现有业务数据和表关系已经存在；历史申请尚无可靠登录用户归属，不能默认属于任意账号。
- 用户确认当前没有统一身份服务，本轮实现项目内账号密码登录。客户经理可认领未分配申请，认领前只看到申请编号及最少业务信息。F1 要求企业补件后重新初检，AI 不作授信决定。

## 期望行为

- 可信身份由服务端建立，后端对每个业务接口及文件、Agent 会话和工具调用校验角色和对象归属，不能信任客户端自报角色。
- 企业只能读取和修改自己所属的申请及材料，支持上传和补件后重新提交；缺失、解析失败或条件不足时不能宣称初检通过。
- 政策问答面向企业客户，在企业用户界面提供入口；客户经理原入口继续可用。
- 政策问答界面参考用户提供的聊天页面：空会话居中显示输入区；问答时保留多轮、流式要点、依据、停止、重试和新对话，不虚构持久历史。
- 客户经理认领未分配申请，认领应使用数据库事务及并发控制；客户经理只能查看及使用自己负责的申请，风控复核范围须明确；跨主体访问拒绝。
- 政策 Agent 的会话绑定用户；客户经理 Agent 的会话、申请与工具调用绑定真实主体和业务权限，不能通过会话 ID 或工具参数越权。
- 登录失败、会话失效、重复提交、状态冲突、空材料、上传错误和 Agent 工具失败有可恢复提示；不改变正式审批边界。
- 用户本轮确认先完成项目内账号密码登录和真实身份授权。第一版账号由本机管理脚本创建；企业账号按申请创建者授权，历史申请默认无企业归属；客户经理认领后按负责人授权；风控可查看待复核、复核中及已提交风控复核的申请，具体状态范围不得扩大到无关申请。
- 不信任浏览器声明的角色或用户 ID；两类对话均绑定服务端登录用户。认领前只提供申请编号和最少必要信息，Agent 工具在每次调用时重新核对最新权限。

## 本轮范围

- 修改认证、权限、数据库模型与版本迁移、业务服务及 API、前端、Agent 工具上下文、必要的隔离验证脚本和文档。
- 不引入真实企业数据，不自动判定授信或执行正式审批；历史数据采用显式管理归属，不覆盖或清空现有记录。
- 不将本地测试账号密码或密钥提交仓库，也不将客户端角色标头作为身份来源。

## 验收

- 至少两个企业、两个客户经理、一个风控及授权分配人员分别验证登录、申请与材料访问；跨企业、跨客户经理和跨 Agent 会话拒绝。
- 企业上传材料并重新提交，验证缺失/解析失败/重复提交/状态冲突分支及初检状态。
- 验证指派后的业务数据、材料下载、Workflow、Agent 工具与审计使用同一可信主体。
- 使用隔离测试库，不清空开发库；运行 `python scripts/check_project.py`、相关接口及浏览器检查，记录实际结果和遗留问题。
