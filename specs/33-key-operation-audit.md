# 任务：关键操作日志

## 来源与目标
- 来源：用户要求记录关键操作的操作者、对象、动作、前后值、时间和结果，用于业务追溯。
- 用户：教学系统管理员、开发和运维人员；避免将申请材料全文写入日志。

## 当前行为
- 状态事件、复核、报告和审批分别持久化；助手工具调用有独立审计，但缺少统一的业务操作日志。
- API 根据登录身份和申请归属授权，状态和报告写入在事务内进行。

## 期望行为
- 申请创建与提交、人工复核动作、审批动作、AI 风险报告保存写日志：操作者 ID/角色、对象类型/ID、动作、有限前后值、UTC 时间、结果。
- 成功业务变更和日志同一事务提交；报告保存但报告生成失败时区分失败结果。指定关键 API 的授权后失败只记录固定错误类别，不记录请求正文或异常文本。
- 管理员只读查询；不记录材料正文、模型输入输出、审批及复核意见、密码、令牌或客户敏感信息。
- 不补造历史日志；不影响既有权限、状态校验与 Agent 审计。

## 本轮范围
- 新增日志表与幂等初始化、日志模块、相关事务及失败记录、管理员查询接口、字段表和隔离验证。
- 不实现生产级日志防篡改、外部日志平台、通用请求审计或历史回填。

## 验收
- 成功状态变更、复核和报告保存有正确前后值、身份、结果；模拟写日志失败时业务事务回滚。
- 可识别关键接口状态冲突或失败；非管理员不能读取日志；验证日志不含材料、意见或密钥。
- 本机库只创建缺失表，不重置业务数据；运行项目检查及隔离回归。
