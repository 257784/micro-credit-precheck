# 任务：风险 Workflow 保存人工复核报告

> 实施记录：风控运行后保存报告，客户经理仍为只读预览。隔离 SQLite 实测材料提交、报告重跑、旧报告冲突和人工复核；独立 MySQL 测试报告持久化与材料快照冲突。未完成真实模型和真实用户浏览器端到端验证。

## 来源与目标
- 来源：用户要求将风险预审 Workflow 输出保存为人工复核所需的报告。
- 用户：风控专员运行预审并人工处理；客户经理只读跟进。
- 目标：同一申请运行风险预审后，可在报告页及复核页读取持久化报告和逐项处理结果，不生成最终授信决定。

## 当前行为
- 风险 Workflow 只返回临时 JSON；ReviewService 只认数据库 reports 表及其逐项关注点。
- 新申请无报告时不能完成复核；Workflow 输入材料可能在运行中发生变化。
- 报告旧契约以页码表示证据，而上传 DOCX 可能只有段落位置；不能伪造页码。

## 期望行为
- 风控专员触发的 Workflow 自动保存新的报告，保留运行状态、风险、缺失、人工复核事项、原文证据与材料快照；客户经理不写报告。
- 模型未启用、缺失、降级和失败均保留真实状态，不能当作无风险；失败及过期报告不能直接完成复核。
- 报告保存时检查申请状态和材料版本，发生并发变化返回 409，不保存过期结果；保存失败明确报错。
- 复核按最新报告逐项确认或修正，状态及报告在事务中校验；用户必须人工决定是否完成复核或要求补件。

## 本轮范围
- 允许调整风险接口、报告与证据契约、Service、Repository、报告及复核页和相关验证文档与脚本。
- 不改政策业务规则、自动审批、不覆盖现有报告；保留旧报告读取和 Agent 工具只读运行。
- 仅使用虚构数据和隔离测试库；保留现有用户改动。

## 验收
- 风险结果保存后刷新仍可读取，同一申请的人工复核逐项保存并进入待审批。
- 检查无报告、失败、材料变化、并发重跑、越权、证据缺失、模型关闭及数据库错误，不伪造报告或审批。
- 执行 `python scripts/check_project.py` 与专项隔离验证；记录无法运行的真实模型和 MySQL 场景。
