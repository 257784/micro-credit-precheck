# 任务：授信申请详情页（核心链路第 2 页）

## 来源与目标

- 需求来源：`../../06-F2-MVP范围表.md` 的“申请详情”和 `../../06-F2交接清单.md` 的“申请详情与进度”。
- 目标用户：风控专员、客户经理。
- 要解决的问题：现有详情缺少产品类型、当前状态和进度轨迹，读取失败也无法从详情区重试。
- 完成后的可观察结果：从列表进入独立详情视图，可返回列表或刷新当前链接，并确认企业、产品、金额、状态、客户经理、进度、材料与报告均属于同一申请。

## 当前行为

- 触发步骤：在申请列表点击一笔申请；页面请求 `GET /api/applications/{application_id}`。
- 实际结果：显示部分申请信息、材料与报告；未显示产品和当前状态，没有状态轨迹，详情错误只有提示文字。
- 相关文件/接口：`frontend/src/ApplicationDetail.jsx`、`frontend/src/App.jsx`、`frontend/src/App.css`、`backend/app/models.py`、`backend/app/data.py`、`mock_data/seed.json`、`docs/data-contract.md`。
- 未确认信息：实际业务状态事件及发生时间尚无来源；本轮新增事件均为虚构教学样例，不代表生产审计记录。

## 期望行为

- 正常输入 → 从列表进入详情视图，展示企业与申请基本信息、产品、状态、客户经理、提交时间、状态轨迹及同申请的材料和报告入口；返回列表保留筛选状态。
- 信息不足 → 无材料或无报告时明确提示人工核实；轨迹只展示已有事件，不推断未记录的状态。
- 错误/冲突 → 详情接口失败时显示错误与“重新加载”；切换申请时旧请求不能覆盖新详情。
- 人工确认点 → 风控专员或客户经理查看并核对信息；本页不提交复核意见或审批结论。

## 本轮范围

- 允许修改：详情页及其直接取数代码、页面样式、状态事件模型与虚构样例、数据关联校验、接口契约、相关测试和运行测试入口；本机验证发现默认 Vite 配置加载失败，允许同步修复前端开发命令。
- 暂不实现：真实材料预览、独立 AI 报告页、风控复核提交、权限控制、MySQL 持久化。
- 必须保持：现有申请、企业、材料、报告字段及只读接口；所有数据为虚构教学数据，失败和无报告不能表示为“无风险”。

## 验收

- 用例1：选择 `APP-DEMO-001`，详情显示同 ID、产品、当前状态、客户经理、两条进度事件、对应材料与报告。
- 用例2：选择 `APP-DEMO-003` 时显示材料解析失败；`APP-DEMO-004` 时显示暂无报告；详情读取失败可重试。
- 测试命令：`python scripts/check_project.py`、`git diff --check`，手动核对正常、错误和空状态。
- 交付证据：代码 Diff、测试输出、页面检查结果及未通过项。
