# 任务：简版风险与待办看板

## 来源与目标

- 需求来源：教师建议补齐简版风险看板；沿用 F1 单申请预审与人工复核边界。
- 目标用户：风控专员和只读跟进的客户经理。
- 要解决的问题：目前只能逐笔在申请列表查看状态，缺少对当前待办与报告异常的集中概览。
- 完成后的可观察结果：用户打开看板即可看到申请状态、报告处理状态的数量，并按申请 ID 进入原有详情链路。

## 当前行为

- 触发步骤：打开前端首页，只显示申请列表；`GET /api/applications` 已返回 `status` 与 `report_status`。
- 实际结果：可筛选单笔申请，但没有汇总视图。
- 相关文件/接口：`frontend/src/App.jsx`、`frontend/src/ApplicationList.jsx`、`frontend/src/formatters.js`、`GET /api/applications`。
- 未确认信息：没有真实风险评分、正式政策判定或已核实的材料齐备规则；看板只汇总现有演示状态。

## 期望行为

- 正常输入 → 按申请状态及最新报告处理状态统计数量，展示每笔申请的状态和报告结果，点击进入同一申请详情。
- 信息不足 → 无报告明确显示“暂无报告”，空列表显示“暂无申请”；不把缺失或失败解释为无风险。
- 错误/冲突 → 列表请求失败时显示错误和重试；刷新、复核状态变化后看板读取最新列表数据。
- 人工确认点 → 风控专员仍需在原有报告与复核页核验材料并提交意见；看板不生成风险评级或审批结论。

## 本轮范围

- 允许修改：前端看板组件及状态汇总、首页导航与样式、相关前端测试、README 和任务卡指针。
- 暂不实现：新后端聚合接口、真实风险评分、正式审批、HTTP 端到端与并发测试。
- 必须保持：现有 `GET /api/applications` 契约、申请 ID 跳转、复核权限与本地记录不变。

## 验收

- 用例1：四笔样例显示四笔申请、两份待人工核验报告、一份解析失败和一笔无报告，点击 `APP-DEMO-001` 进入详情。
- 用例2：复核后列表状态变更时看板计数更新；空列表、请求错误、加载中均有明确提示；未知报告状态不丢失计数。
- 测试命令：`python scripts/check_project.py`、`git diff --check`；若本机旧构建目录不可写，单独记录该失败并用新的输出目录核对前端构建。
- 交付证据：代码 Diff、自动测试与页面检查结果、未通过项及原因。
