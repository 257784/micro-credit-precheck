# 任务：十笔虚构申请及双 Workflow 验证

## 来源与目标
- 为后续 Agent 和 Workflow 评估准备 10 笔虚构企业申请及带正文的 DOCX 提交材料。
- 目标用户为教学演示中的客户经理和风控专员；结果仅用于教学，不构成授信决定。

## 当前行为
- MySQL 业务表已清空，原材料样例及自动测试已删除；两个 Workflow 从申请和上传材料读取数据。
- 文本解析仅支持文字型 PDF/DOCX 的字段标签；风险规则目前只对设备类样例做部分字段对比。

## 期望行为
- 10 笔不同申请有可读取正文的虚构材料，包含正常、材料缺失、字段缺失、主体不一致、金额差异及解析失败场景。
- 通过申请 ID 从 MySQL 查询申请与上传材料；两条 Workflow 对每笔申请运行，保留实际结果及未通过项。
- 信息不足、解析失败或证据缺口不得被描述为无风险或审批通过；人工复核仍是必要环节。

## 本轮范围
- 允许新增教学数据生成及导入脚本、虚构 DOCX、场景清单、验证报告和必要文档；不变更政策、业务规则或现有记录。
- 导入前检查目标 ID；重复导入不得覆盖已有申请、文件或复核；失败需保留真实错误及可恢复信息。
- 保留现有 API、数据库约束和已录入用户数据。模型调用默认为关闭；未调用真实模型须在报告说明。

## 验收
- MySQL 中可读取 10 笔申请及真实内容材料，DOCX 可通过上传接口读取。
- 按 10 种场景逐笔运行材料检查和风险预审，正常、异常和错误状态与预期比较。
- 执行 `python scripts/check_project.py`；交付场景、测试结果与限制。
