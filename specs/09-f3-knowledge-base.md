# 任务：F3 RAG 虚构业务文档语料

## 来源与目标

- 需求来源：F3 阶段整理知识资料；用户进一步要求用独立政策和业务制度原文替代代码现状说明，作为 RAG 的检索语料。
- 目标用户：知识维护人员、风控专员和后续检索功能开发者。
- 要解决的问题：上一版混入运行文件、样例解释和开发边界，缺少能直接回答业务问题的独立制度条款。
- 完成后的可观察结果：五份虚构业务文件独立存放于 `corpus/`；管理说明、硬规则映射和评测答案在检索范围外。

## 当前行为

- 触发步骤：阅读上一版 `docs/f3-knowledge-base/` 的政策摘要、材料口径和复核指引。
- 实际结果：正文主要解释 F2 样例和运行能力；F2 仍只有 `KNOW-DEMO-001`，未实现 F3 检索。
- 相关文件/接口：`../05-AI能力嵌入点.md`、`../06-F2-MVP范围表.md`、`../06-F2交接清单.md`、`docs/data-contract.md`、`backend/app/reviews.py`。
- 未确认信息：真实机构政策没有来源。本轮按用户要求原创虚构机构政策，新增材料及核验条件明确标为教学拟定稿；额度、利率、文件大小和页数限制不设定。

## 期望行为

- 正常输入 → 仅从五份业务正文检索适用条款，引用文号、版本和条号，保留例外及替代条件。
- 信息不足 → 标记“未找到适用依据／待人工确认”，不补造政策或推断无风险。
- 错误/冲突 → 过期、范围不符或相互冲突的条目停止作为依据，交由知识维护人员核对。
- 人工确认点 → 文档可用于离线教学检索；将新条件接入运行系统前另行确认规则和数据兼容性。风控专员核对单笔材料，审批人员负责正式决定。

## 本轮范围

- 允许修改：本任务卡和 `docs/f3-knowledge-base/`；替换上一版六份混合说明，新增五份正文、管理资料与导入白名单。
- 暂不实现：RAG 服务、向量索引、真实政策接入、产品准入阈值、真实审批、F2 代码和种子数据修改。
- 必须保持：F1/F2 角色与状态边界、现有 `KNOW-DEMO-001` 的原文与版本、所有数据均为虚构教学数据。

## 验收

- 用例1：五份正文脱离仓库仍可阅读，包含文号、版本、产品、条款、替代条件和例外；无代码路径或单笔演示申请编号。
- 用例2：可按条款回答收入资料期间、报价单替代、二手设备材料、补件和人工复核问题，未规定事项明确无依据。
- 用例3：manifest 仅白名单五份正文；管理文件与评测答案不入库；所有交叉引用和条款数量一致。
- 测试命令：`python scripts/check_project.py`、`git diff --check`；文档交叉链接和编号人工核对。
- 交付证据：文档 Diff、链接检查结果、自动检查结果及未确认事项。
