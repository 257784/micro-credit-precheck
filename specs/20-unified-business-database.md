# 任务：统一业务数据库与环境变量连接

状态：已执行真实MySQL迁移，原数据及状态已核对；真实MySQL存储/并发测试与双Workflow回归通过。依赖锁文件同步受网络限制，虚拟环境orjson DLL在Agent执行环境被拒绝加载，详见docs/architecture/database-migration-report.md。

## 来源与目标

- 用户要求统一数据来源，通过backend/.env连接数据库；沿用项目原定MySQL方向。
- 企业、申请、材料记录、解析结果、报告、状态记录和复核记录统一以MySQL为业务事实来源。
- JSON仅保留为初始化及测试样例，旧SQLite只作为迁移来源和回退备份，运行时不得同时拼接三种业务存储。

## 当前行为

- applications Repository从seed.json加载；复核动作在reviews.sqlite3；上传记录在documents/files.sqlite3。
- 申请最新状态由JSON基础状态和SQLite动作合并得到；迁移必须保持最终状态和历史记录。
- 原件为文件，向量为Chroma；它们不是要替代的业务关系数据库。
- 2026-10-29安全检查未检测到有效DATABASE_URL；未发现名称含MySQL/MariaDB的Windows服务，这不能证明机器没有其他方式部署MySQL。项目虚拟环境有pymysql，全局测试环境没有。

## 期望行为

### 连接与生命周期

- 通过环境变量DATABASE_URL配置MySQL连接，运行命令加载backend/.env；真实凭据不入库、不提交、不显示在日志或异常中。
- core/config负责解析设置，db负责engine、session和事务；API在生命周期中初始化连接，业务模块导入不触发数据库连接。
- 缺配置、驱动不可用、连接失败均有明确安全错误；选定MySQL后不静默退回JSON/SQLite。
- 自动测试可以显式注入独立测试数据库；不得复用用户开发库，更不能自动清库。

### 表与关系

| 表 | 主要内容与约束 |
| --- | --- |
| enterprises | 企业主键、名称及已有业务字段 |
| applications | 申请主键、enterprise_id外键、产品、金额、当前状态、提交时间 |
| materials | 材料主键、application_id外键、类别、版本、文件信息、存储引用、摘要、解析状态/结果与来源 |
| reports | 报告主键、application_id外键、生成时间、状态、结构化内容、规则/知识版本 |
| status_events | 事件主键、application_id外键、事件时间及动作信息 |
| review_actions | 动作主键、application_id外键、可空report_id外键、人员、时间及逐项复核内容 |
| knowledge_items | 现有教学知识编号、版本及内容；用于兼容历史报告引用 |

- 申请按企业、状态/提交时间建立查询所需索引；材料按申请/类别/版本设唯一约束，按申请检索；报告、事件和复核按申请与时间索引。
- 保留现有JSON结构字段可使用MySQL JSON，不为本轮引入不必要的银行数据模型。
- 实际DDL、ORM、ER图和测试必须一致；外键不默认级联删除历史证据。
- 原件继续存于文件目录；MySQL记录路径/存储键、摘要、版本。Chroma保留向量能力，不把它作为申请业务数据源。
- 本轮不改变风险Workflow结果“临时返回”的既有边界；已有持久化报告全部迁移，新增每次运行报告落库若需要另行明确，不能偷偷替代旧复核关联。

### 迁移

1. 生成只读预检清单：旧数据数量、主键重复、悬空关联、实际状态、文件存在性、类别版本冲突。
2. 迁移前保留原JSON、SQLite和文件，不删除、不重置用户已操作的记录。
3. 将同申请的旧材料和上传材料归一；同类别版本冲突不得直接覆盖，使用可解释映射保留材料ID和证据关联，预检报告列出调整。
4. 显式执行迁移，使用事务及迁移版本记录；同一来源重复执行不重复插入，不覆盖新库中后续用户修改。
5. 外键依赖顺序导入，核对记录数、关键关联和最终申请状态；失败回滚业务写入，保留真实错误原因且不泄漏凭据。
6. 成功验证后切换Repository，运行时只读写MySQL。旧源保留只读备份，不再持续参与业务查询。

### 服务行为

- API路径、参数、错误响应、SSE、教学权限和报告字段不变。
- 开始/提交复核在同一事务内核对当前状态、保存动作、修改状态；并发重复提交仅允许一次有效变更。
- 上传版本分配和幂等受事务/唯一约束保护；原件写入与数据库记录不能形成未说明的孤立成功状态。
- 两个Workflow、Agent工具和脚本通过Repository/Service读取同一个业务数据源，禁止继续从seed.json补齐线上申请。

## 本轮范围

迁移收尾：隔离app/legacy_sqlite中的旧连接、DDL与读写实现；运行入口仅使用SQL Repository。保留只读迁移与显式隔离测试，增加禁止业务模块依赖旧SQLite的架构回归。

db连接/ORM/迁移、config、repositories、services、API依赖装配、环境示例、测试、迁移脚本和说明文档；必要时同步Workflow材料适配。保留政策、提示词、向量快照和业务规则。

不实施MySQL生产部署、用户认证升级、对象存储、Chroma替换、自动审批或真实客户数据接入。

## 验收

- 有效.env连接MySQL，重启后数据仍在；缺配置和不可达数据库安全失败。
- 迁移前后企业/申请/材料/报告/动作数量及关联一致；已有审批前状态不退回初始状态。
- 重复迁移不重复数据、不覆盖后续操作；冲突/失败有记录并可回退。
- 移除运行时对seed和旧SQLite的依赖；修改旧源不影响数据库查询结果。
- 真实MySQL验证外键、唯一索引、事务回滚和并发复核；SQLite测试不能替代此验收。
- 完整性、风险预审的正常/异常/金额差异三组联调保持预期。
- 全部自动检查通过，并生成迁移及测试报告；未运行真实MySQL时标明未验收。
