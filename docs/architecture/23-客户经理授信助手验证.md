# 客户经理授信助手：实现与验证记录

## 实现

- 增加独立助手会话与SSE入口、首页及申请详情入口，服务端维护单进程会话和最近消息。
- ToolClient调用DeepSeek的非流式tools接口；客户端只看到工具进度和依据工具结果整理的最终答复，模型自由文本不直接输出。工具限定8次、模型请求6次、单轮60秒。
- 工具执行器使用Pydantic白名单和服务端教学上下文，只允许APP-FICT-001至010；调用既有Service，模型不能指定身份、权限或开启Workflow的额外AI调用。示例身份与服务端管理员开关均不是生产认证。
- assistant_tool_audit记录工具意图及结果、主体、申请、会话、请求、运行ID、调用ID、时间和耗时；不保存完整正文与密钥。显式脚本创建表，重复执行不清表。默认客户经理不能查询审计，服务端演示管理员模式可查询。
- 检索配置缺失时search_policy明确返回不可用；未恢复旧政策问答配置。Agent的模型决策仍需DeepSeek网络和有效配置。

## 实际验证

- `python scripts/check_credit_assistant.py`：12项隔离测试通过，包含白名单/参数/范围拒绝、审计失败拒绝、受控审计查询、假模型工具调用、重复调用ID、预算拒绝、取消、SSE、会话重放与跨演示主体拒绝。只使用临时SQLite和假模型。
- `python scripts/check_credit_assistant_workflows.py`：使用临时SQLite及真实虚构DOCX验证正常、缺报价、金额差异、解析失败四组；两条Workflow均经过助手工具调用，申请状态及复核记录不变。
- `python -c "import fastapi,sys,runpy; sys.path.append('backend/.venv/Lib/site-packages'); runpy.run_path('scripts/check_credit_assistant_mysql.py',run_name='__main__')"`：在随机创建并删除的独立MySQL测试库验证上述四组，通过；未修改开发库申请或复核。显式审计表初始化脚本在开发库执行两次成功，保留已有业务数据。
- 浏览器使用模拟SSE验证助手页面、工具轨迹和回答展示。另通过本地HTTP验证创建会话、未提供ID时的追问及普通用户审计查询403。浏览器未对真实DeepSeek流量做端到端验证。
- `python scripts/check_project.py`检查空白、Python语法和前端构建；此命令本身不运行新建的隔离Harness测试。

## 未覆盖与限制

- 真实DeepSeek工具调用做过一次最小连通性尝试，返回安全错误码`network_error`，没有收到模型响应；因此模型工具调用协议、真实网络、延迟和效果尚未通过验证，不能以假模型结果替代。
- 当前执行环境从backend/.venv导入FastAPI时orjson DLL被拒绝；验证MySQL时用全局Python并复用现有虚拟环境内的PyMySQL。实际用户终端是否遇到该问题需单独确认。
- 还未完整验证浏览器断网、取消、用户切换全部交互以及真实多用户并发。审计结果写入失败时返回失败，但若进程在工具执行期间崩溃，意图记录可能保留started，不能推断成功。
- `CREDIT_DEMO_ADMIN=1`影响整个服务进程，不能用作真实认证或部署到不可信网络。单进程内存会话重启后丢失，不支持跨进程一致性。
- 现有业务规则根据教学政策重建，真实正确率、政策检索及RAG配置未在本轮恢复。审计仅覆盖助手工具，不代表已有全部HTTP接口有生产级权限或审计。
- 假模型用例覆盖若干格式和注入条件，不能证明面对任意恶意内容都有效；当前答案按工具结果直接整理，不能当成语义正确性的保证。
