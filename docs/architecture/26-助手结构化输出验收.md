# 客户经理授信助手结构化输出验收

## 交付

- `backend/app/schemas/assistant.py`定义版本1.0结果及嵌套对象，禁止额外字段。结果区分申请事实、材料问题、风险线索、政策检索来源、信息缺口、人工复核与局限。
- `backend/app/agents/assistant_result.py`仅从本轮工具结果组装；工具申请ID或Workflow申请ID不匹配时失败。材料引用必须匹配同一申请、ID、版本及段落中的原文；不可核验的风险线索被移除并列为待人工核对，金额差异要求至少两侧证据。规则政策引用核对教学语料，本轮检索来源另行比对当前语料块；这些检查不等于证明语义蕴含。
- 助手SSE发送进度、完整`result`、兼容摘要`answer`和`done`；依赖失败的done为partial。成功轮次重放相同结果和run_id，异常只返回error。页面只在result和done均完整时展示，并标注工具内容及不可信材料原文。
- 结果为本轮会话内存数据，未纳入历史报告或复核表；不会修改业务状态。聊天条件、演示身份和审计边界沿用第23轮，非真实用户认证。

## 验证结果

- `python scripts/check_assistant_result.py`：10条通过，覆盖双边证据、跨申请/伪造引文、额外审批字段、失败降级、空申请追问、真实/虚构政策引用、非法材料引用、SSE失败与重放。
- `python scripts/check_credit_assistant_workflows.py`：临时SQLite与真实虚构DOCX运行正常、缺报价、金额差异、损坏文件四组，金额差异的两侧120000/150000在结构结果中有可核验出处，业务状态和复核记录不变。
- 隔离MySQL测试库执行`scripts/check_credit_assistant_mysql.py`上述4组通过；原开发数据库数据未重置。历史Harness与风险测试仍通过。
- 浏览器使用模拟SSE测试结构分区、双侧证据和JSON折叠区；截图`structured-assistant-browser.png`为模拟结果，不是真实DeepSeek输出。首次浏览器检查因定位器匹配到隐藏JSON和可见文本而报严格模式错误，收窄定位器后通过。
- `python scripts/check_project.py`检查空白、Python语法与前端构建，不包含上述独立测试。

## 边界与剩余工作

- 未调用真实DeepSeek，真实工具选择及端到端对话仍需在用户可用环境验证。政策来源取本轮检索返回，若没有调用政策工具则不展示来源，不把相似候选当作已回答。
- 引文校验能核对文本存在和归属，但不能保证推理的语义正确；风险和材料问题的描述来自工具，仍标为待人工核验。教学规则为按资料重建版，不能推断生产政策。
- 旧文本回答仍在内部生成用于循环兼容，SSE的answer事件仅为结构化摘要；新页面以result事件为准。旧客户端如只消费answer，不会看到所有细节。
