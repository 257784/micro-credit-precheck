# 关键操作日志：实现过程与字段表

## 实现过程

1. 梳理现有记录：申请状态事件、人工复核记录和助手工具审计分别保存在不同位置；新增 `operation_audit` 作为关键业务动作的统一查询入口，原记录保留。
2. 在申请创建/提交、复核、审批、风险报告保存的数据库事务中写入日志。业务写入和成功日志一起提交或回滚；风险报告未完整生成但已保存时，日志结果标记为 `degraded`。
3. 已登录且有权访问该申请的请求，在指定操作返回 409、422、500 或 503 时，由 API 中间件另起事务记录失败和固定原因代码。该记录不保存业务异常原文；鉴权前失败、403、404、其他接口和网络层失败不在本轮覆盖范围内。
4. 管理员可在账号管理页面读取最近记录，也可调用 `GET /api/operation-audit?application_id=申请编号&limit=50`。接口限制为管理员，返回最多 100 条。

## 日志字段

| 数据库字段 | 含义 | 示例 / 约束 |
|---|---|---|
| `id` | 日志唯一标识 | 随机生成 |
| `occurred_at` | 记录时间 | ISO 8601，UTC，含时区 |
| `actor_id` | 已认证操作者用户 ID | 不记录账号密码或令牌 |
| `actor_role` | 操作时的服务端角色 | 如 `enterprise`、`risk_reviewer` |
| `object_type` | 操作对象类型 | 当前固定 `application` |
| `object_id` | 被操作的申请 ID | 授权后记录 |
| `action` | 固定动作码 | `submit`、`review_complete`、`risk_report` 等 |
| `before_value` | 写入前的有限字段 | 例如 `{"status":"风控复核中"}`；未知时为 `null` |
| `after_value` | 写入后的有限字段 | 状态或报告 ID 与分析状态；失败时为 `null` |
| `result` | 操作结果 | `success`、`failed`、`degraded` |
| `reason_code` | 失败类别 | `state_conflict`、`invalid_input`、`dependency_failure`，成功时为 `null` |

允许记录的前后值只有状态、报告 ID 和报告分析状态；状态和报告 ID 按规则校验。日志不写材料全文、模型输入输出、审批及复核意见、密码、Cookie 或密钥。操作 ID、用户 ID 和申请 ID 仍属于业务标识，日志需要按权限管理。

## 动作和事务

| 动作码 | 触发动作 | 前后值 | 成功日志与业务变更 |
|---|---|---|---|
| `create_draft` | 企业创建草稿 | 前值空，后值草稿 | 同事务 |
| `submit` | 企业提交或补件后重新提交 | 申请状态前后值 | 同事务 |
| `review_start` / `review_complete` / `request_supplement` | 风控开始、完成复核或要求补件 | 申请状态前后值 | 同事务 |
| `approval_start` / `approve` / `reject` | 审批人员开始审批或记录结果 | 申请状态前后值 | 同事务 |
| `risk_report` | 风控生成并保存 AI 风险报告 | 申请状态、报告 ID、报告分析状态 | 同事务；报告不完整为 `degraded` |
| `review_submit` | 提交复核被拒绝 | 失败时前后值为空 | 业务事务结束后单独记录 |

失败日志记录在独立事务；如果数据库或日志表不可用，不能保证失败事件被留存。日志表没有防篡改、保留期限或外部备份机制，不能作为生产级审计设施。不会为历史业务记录补造日志。后续可以添加专门的运维审计角色，目前沿用管理员权限。

## 初始化与验证

在 F2 根目录执行 ` .\backend\.venv\Scripts\python.exe scripts\init_operation_audit.py `，仅创建缺失表，不修改已有业务数据。验证命令：

```powershell
.\backend\.venv\Scripts\python.exe scripts\check_auth_integration.py
.\backend\.venv\Scripts\python.exe scripts\check_permissions_submission.py
.\backend\.venv\Scripts\python.exe scripts\check_state_transitions.py
python scripts/check_project.py
```

隔离测试覆盖成功与失败日志、管理员查询限制、敏感内容不进入日志，以及日志写入失败时事务回滚；测试不使用开发数据库。
