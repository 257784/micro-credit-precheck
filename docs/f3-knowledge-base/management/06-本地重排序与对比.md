# 本地重排序与对比（不参与入库）

本轮在已有纯向量检索后增加本地 BAAI/bge-reranker-v2-m3，沿用默认召回 8 条。不生成回答，也不修改向量或活动索引。模型使用 Transformers 联合读取问题与条款原文，输出原始 logit，越高表示模型判断越相关；分数不是余弦相似度、正确率或审批概率。本轮不设分数阈值。

## 配置与实现

- `backend/app/reranker.py`：按需加载、配对评分、稳定排序与整批回退；单个实例在批量评测中复用模型。
- `backend/reranker.json`：本地模型目录、最大问题—条款 token 数 2048、batch_size=1；与向量配置分开，不需要重新入库。
- `scripts/knowledge_base.py`：查询入口；`scripts/evaluate_reranker.py`：真实候选的重排前后对比。
- 不改用户已有的 `scripts/check_reranker.py`，该文件仍用于独立模型初测。

CPU 使用 float32，CUDA 使用 float16。初次会读取全部模型文件计算指纹，并加载权重；需要等待且消耗内存。两种模型可分别选择设备。模型加载仅使用本地文件，`local_files_only=True`、`trust_remote_code=False`，无额外下载或新依赖。

2048 限制包括问题、正文和特殊 token。超长时整批回退，不使用截断后的政策，避免例外和替代条件被丢弃。

## 查询

在项目根目录执行，纯向量查询仍可使用原命令：

```powershell
.\backend\.venv\Scripts\python.exe scripts/knowledge_base.py query --product equipment --text "没有签订设备采购合同，可以用报价单吗？" --top-k 8
```

开启重排并保留前 5 条：

```powershell
.\backend\.venv\Scripts\python.exe scripts/knowledge_base.py query --product equipment --text "没有签订设备采购合同，可以用报价单吗？" --top-k 8 --rerank --context-k 5
```

显卡已经确认可用时，可追加 `--reranker-device cuda`；向量模型设备另由 `--device` 控制。重排默认 CPU、context-k=5。需要 `1 <= context-k <= top-k <= 20`；实际候选不足时返回全部已有候选，不补足、不复制。`--context-k` 只在 `--rerank` 时有效。

## 命令行返回结构

未启用重排时，仍是原有的 `notice` 与 `results`，不加载重排依赖。

启用后，顶层 `results` 是最终选择的条款，`reranking` 包含状态、错误、候选数、耗时、模型标识与文件指纹、原始候选及完整重排列表：

| 字段 | 含义 |
| --- | --- |
| `reranking.status` | `success` 成功；`empty` 无候选；`fallback` 评分失败并使用向量原序 |
| `reranking.error` | 正常为 null；降级记录异常类型与原因 |
| `reranking.original_results` | 本次召回的全部原始候选，按向量排名排列 |
| `reranking.ranked_results` | 全部重排候选；失败时仍为向量原序 |
| 条款 `vector_rank` | 1 开始的原始向量排名 |
| 条款 `rerank_rank` | 1 开始的重排排名；降级时 null |
| 条款 `rerank_score` | 原始 logit；降级时 null |
| 条款原有字段 | `id`、`text`、`metadata`、`cosine_distance` 均保留 |

相同得分按原向量排名稳定排序；调用不修改传入的原候选。没有候选时不读取重排权重，也不将空结果解释为无风险或有依据。

重排缺文件、加载/推理异常、超长、分数数量不符或 NaN/Infinity 时，整批使用原排序，不混合部分已成功分数。查询降级仍返回可查看的候选，命令退出码为 0，但必须检查 `reranking.status`；配置不合法、原始检索失败时返回非零，不把检索失败误标成重排降级。默认 5 条只是本轮实验上下文数量，尚未据真实对比认定最优。

## 对比测试

```powershell
# 不运行模型，校验配置与标签
.\backend\.venv\Scripts\python.exe scripts/evaluate_reranker.py --validate-only

# 实际每题召回8条，在同一候选池中对比重排前后Top-3/5
.\backend\.venv\Scripts\python.exe scripts/evaluate_reranker.py --device cpu --reranker-device cpu
```

测试仍用原 16 题，不将题目入库；从当前活动索引实际查询 8 条，不从旧 Top-20 报告取前缀。先完成向量检索，再加载重排模型。输出：

```text
backend/.data/knowledge-base/reranker-evaluation/report.json
backend/.data/knowledge-base/reranker-evaluation/report.md
```

报告包括：同一成功题集合的 Recall、Hit、全依据覆盖、上下文字符数，逐题召回增减、前后完整排名、来源与得分、运行/数据/模型指纹。Top-8 候选覆盖仅列原序，重排不会改变这批候选的总覆盖。

失败题从前后两侧同时排除，不计为有效模型对比；原始结果、原因仍保留。存在失败则状态为 `incomplete`，命令返回 1；全部评分完成为 `complete`，不代表质量一定改善。失败发生在检索阶段时不产生本次对比报告，须注意旧报告的 `run_at`。成功运行会覆盖上次报告，需留历史时先复制。

逐题耗时包含该次加载/校验和评分，首题是冷启动、后续复用模型；仅用于本轮单次观察，不代表服务延迟。无依据题不计召回，标签非穷尽；分数无法证明已有充分证据。Q11/Q15 的候选遗漏须继续保留，不能声称重排已解决。

依据结果决定 context-k：比较前 3/5 的覆盖及完整条件是否保留，而非单看首条排名。尚未测得结果时不自动设置重排默认开启，不决定最终上下文数量。

官方实现参考：[BAAI 模型说明](https://huggingface.co/BAAI/bge-reranker-v2-m3)。
