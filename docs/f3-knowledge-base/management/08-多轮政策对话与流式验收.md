# 多轮政策对话与要点级流式验收

本轮落实已批准的 `specs/14-conversational-policy-agent.md`。新页面不要求选择贷款产品，直接输入用途或政策问题；后端保存临时会话，每轮重新检索，并在上游生成结束前逐条推送已核对引文的完整要点。既有 `/api/policy/ask` 和 CLI 单轮调用保留。

## 本机启动及使用

沿用已配置的 DeepSeek 后端环境；不需要重新下载模型或重建索引。本轮把锁文件中原有的 httpx 0.28.1 声明为直接依赖，没有升级其他锁定包。在 `backend` 目录同步并启动：

```powershell
python -m uv sync
python -m uv run --env-file .env uvicorn app.main:app --reload
```

前端 `npm run dev` 后点击“政策问答”。不要使用多 worker：会话保存在本进程内存。开发热重载会清空会话，与后端重启相同。

- 先输入“没签合同能用报价单吗？”，再回答用途“准备购置生产设备”，核对是否继续回答原问题。
- 接着问“那二手的呢？”，检查是否承接设备语境并重新引用当前轮条款。
- 再说“刚才说错了，是采购原材料”，核对是否清除设备相关范围和资料要求。
- “客户经理能不能完成复核”检索共通规则；“两种贷款有什么区别”按两产品范围解释，不能合并要求。
- 生成时要点及原文分批出现，完成前标注未完成。停止或失败会撤回本轮临时正文，保留候选供查看，不能当作完整答案。
- “新对话”与“恢复对话”控制当前标签页。每条消息引用单独定位，不与旧轮S1混淆。

浏览器取消等待不保证已产生的上游计算费用撤销。同步 embedding 在工作线程中运行，取消不会强杀正在计算的线程，但其迟到结果不会继续生成或写入新会话。

## 状态、路由与来源

`backend/app/conversations.py` 管理单进程会话和原子提交：空闲30分钟、最多50个会话、每会话最多20个完成轮次；另设40次总尝试上限，防止失败记录无限占用内存。前端 sessionStorage 只存随机会话编号，不存凭据；这不是生产鉴权。

每轮消息只传当前问题和请求编号，服务器选择最近6个完整轮次、历史合计最多12000字符；失败、停止、部分输出不作为成功历史。当前用途/日期/设备属性在结构化状态中记录，并包含用户原文片段和用户消息ID。原文匹配不等于材料核实，意图提取的语义正确性仍需真实评测。

`backend/policy-products.json` 用两份政策的用途/范围条款作为产品目录。明确产品名称/文号直接解析；用途、指代和选择请求由 DeepSeek 按目录识别；用途路由要求附用户原文事实，沿用路由只能沿用已有范围。未知、冲突、非法路由不能变成产品过滤条件。增加产品需要同步目录、元数据与测试。

单产品继续使用产品过滤；共通问题使用所有已登记产品的适用交集；比较/介绍保留两产品范围原文，比较再按产品补充向量结果。直接读取范围条款的来源 `cosine_distance=null`，不能把固定挑选的条款伪装成距离0的近邻。

共通条款中的设备例子不会自动成为经营周转用户的缺口：提示明确限制，并增加常见串用表达的校验。这不是完整语义验证；仍需人工核对通用段落、条件和例外。

## 实际流式链路

`async_deepseek.py` 使用 httpx AsyncClient，DeepSeek `stream=true`，异步读取 SSE；关闭上下文会关闭连接，不转发 reasoning_content，不自动重试。单轮总预算120秒，另有上游读取超时和1MiB缓冲上限。

`stream_json.py` 用 JSON 解码器和顶层字段/数组状态读取完整 statement，不按花括号正则拆分。完整要点先校验结构、来源和引用原文，才发 statement；最终完整 JSON 再检查重复键、全部结构及要点一致性。没有伪造打字延时。

`conversation_api.py` 提供有界队列、5秒注释心跳和递增seq。每帧包含会话、请求与助手消息编号，顺序为 meta → status/scope → sources → statement → done。澄清可直接 clarification → done；故障用error，部分正文撤回，失败轮不提交成功历史。只有done表示本轮完成。

要点级流式意味着首要点需要等这段解释与引文完整生成。长要点或单要点可能晚一些出现，不能把收到status当作已经产生答案。

## API 与兼容

- `POST /api/policy/conversations` 创建，返回随机 conversation_id。
- `GET /api/policy/conversations/{id}` 恢复历史、讨论状态及在途轮次。
- `POST /api/policy/conversations/{id}/messages/stream` 接收 question、request_id、可选retry_of；不接受产品、客户端历史或system消息。
- `DELETE /api/policy/conversations/{id}` 幂等结束，返回204。

请求非法422，过期/未知会话404，在途或轮数限制409，会话容量限制429；流开始后的错误用error事件。相同已完成request_id只回放meta和done，不再次调用模型；新重试请求须关联未完成的同一个问题。

后端提交done前原子保存完整响应和讨论状态。网络在提交后中断，点击恢复可读取保存结果。实际产生的候选与回答只保存在临时会话，重启后不可恢复。

## 多轮验收入口

默认只列计划，不调用 API：

```powershell
.\backend\.venv\Scripts\python.exe scripts/evaluate_policy_conversation.py
```

先在页面单题成功，再运行本机HTTP多轮验收，可能产生 DeepSeek 费用（脚本不读取凭据，凭据由后端加载）：

```powershell
.\backend\.venv\Scripts\python.exe scripts/evaluate_policy_conversation.py --run --limit 8
```

用例位于 `management/conversation-cases.json`，有9段对话，默认执行1段，最多9段；另须在浏览器做停止/断网失败的人工操作。测试文件不入库。报告在 `backend/.data/knowledge-base/conversation-evaluation/report.json` 和 `report.md`，包含每轮全部事件、服务器路由、引用、首状态/首要点/done时序以及人工复核项；运行完成不等于质量通过。

请分别核对：范围正确、澄清是否必要、改用途是否生效、条件和例外是否完整、引文支持解释、无产品内容串用。每轮引用匹配无法代替这些判断。失败/中断可能只保留部分JSON，旧Markdown须核对运行时间。

## 本轮验证边界

Agent 不读取本机凭据，不执行真实付费调用。自动化使用受控模型和HTTP替身，不能据此宣称真实 DeepSeek 已通过上述多轮质量验收。当前会话的数值库DLL仍可能限制真实检索，用户先前已报告本机可运行；本轮需在该终端测试新流程。

开发中发现并修复了两处上游资源释放问题：局部引用校验失败时需显式关闭上游异步生成器；下游在队列等待期间取消时也要关闭被挂起的Agent生成器。现在使用显式异步关闭上下文，并测试停止/局部错误后连接已关闭。

官方接口参考：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[HTTPX异步流](https://www.python-httpx.org/async/)。
