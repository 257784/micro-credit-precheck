# 真实 DeepSeek 三组材料测试报告

## 结论

在用户授权后，通过本机运行中的后端真实调用模型，正常、内容不符合、金额差异三组均完成政策检索与模型输出校验。两个异常场景识别方向符合预期，没有作授信批准、拒绝或欺诈定性。

这是三组样例的一次实测，不是风险识别准确率评测。正常组提醒偏多、模型引文有时不能单独支撑跨文档比较，仍需优化。

## 测试方式

- 调用地址为本机后端 `/api/applications/APP-DOC-{case}/risk-precheck`，传入 `use_model=true`，后端使用已有DeepSeek配置；没有替换检索器或模型客户端，没有读取或显示API Key。
- 每组先经真实HTTP上传六份DOCX，再调用材料完整性检查与风险预审，明确声明设备为全新。
- 脚本：`python scripts/verify_document_model_live.py --run`。该命令会真实调用服务，可能产生费用，不属于默认单元测试。
- 原始结构化结果：`workflow-evidence/document-model-live.json`，包含开始时间、每组耗时、材料检查和完整风险输出。
- 后端响应未提供实际模型型号及token计费信息；不猜测实际型号或费用。下表耗时是客户端测得的整个风险预审请求时间，不是纯模型耗时。

## 代表性回答与证据

内容不符合组指出：报价单未载明具体交易报价，价格依据是否充分需人工核验。其引用实际上传正文“本文仅为宣传介绍，未提供具体交易报价”，方向正确。

金额差异组指出：采购计划与报价单的单价和总价不一致；操作建议明确列出60000/75000和120000/150000，要求核实原因，不自动调整额度。该差异与独立规则核对一致。

正常组没有凭空制造数值冲突，但输出了6条人工复核提醒，主要是重复核对已提供的信息。应区分实际异常和例行核验清单，不宜把提醒条数解释为风险数量。

## 发现的问题

1. 正常组噪声较多。主体对应、用途和价格口径已有可核对内容，模型仍泛化要求人工核验；属保守提醒，不等于真实异常。
2. 跨文档证据展示不完整。金额差异项部分只引用采购计划120000或申请金额120000，另一侧150000虽然存在于输入中，但未在该条引文里同时显示；报价编号本身也不能证明金额不同。应允许每条模型线索绑定多份材料证据并检查结论与证据的关联。
3. 未签约材料提醒偏宽泛。政策允许报价单加未签约说明，当前模型仍建议核验甚至提出补件；不得将未签约本身当成缺项，应更明确检查允许的替代组合。
4. 输出来源标签仍有历史适配残留：真实上传全文在部分模型证据中标成teaching_excerpt，并且位置显示“实际上传文件段落”而非具体段落号。原文确实来自本次上传文件，但溯源展示需要进一步细化。

这些问题不阻断本轮真实调用链路，但意味着“3/3调用成功”不能写成“准确率100%”。本轮没有擅自更改提示词或重新调用来覆盖原始结果，保留上述输出供下一轮优化对照。
