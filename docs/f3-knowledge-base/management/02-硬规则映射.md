# 业务条款与硬规则映射（不参与检索）

政策全文可以用于问答和引用；其中确定的检查条件还必须落实为规则配置或代码。RAG 负责查明依据，程序负责计算、关联和拒绝非法操作，人工负责核验材料真实性及语义例外。以下是接入设计，未新增运行规则。

| 规则号 | 条款依据 | 应由程序执行的条件 | 人工判断及当前实现情况 |
| --- | --- | --- | --- |
| R-01 | CC-MAT-001 第一至四条 | 按产品匹配共通和产品专属清单；必要条件未知时输出“待核实”，不默认齐全 | 新清单未接入；不能由语义检索是否命中决定材料齐全 |
| R-02 | CC-POL-001 第五条 | 按提交月份计算前三个完整自然月；经营不足三个月时采用实际经营期间分支 | 经营起始日、覆盖区间须有可验证数据；目前缺此结构化字段，未实现 |
| R-03 | CC-MAT-001 第三条 | 经营收入资料采用明确的组合规则；被引用的具体订单/合同触发相应材料要求 | 是否足以证明具体收入仍须人工核验；未实现 |
| R-04 | CC-POL-002 第五条；CC-MAT-001 第四条 | 价格依据为合同，或报价单加未签约说明；缺少任一替代条件不能判齐全 | 报价内容适用性由人工核验；未实现 |
| R-05 | CC-POL-002 第七条 | 确认二手设备时要求 M-E03；新设备不要求；属性未知则提示核实 | 新旧属性不能由模型猜测；未实现 |
| R-06 | CC-MAT-001 第五条 | 格式为 PDF/DOCX；不可读取时反馈原因，不把读取成功等同内容核验成功 | F2 仅有 Mock 状态，无真实文件检查 |
| R-07 | CC-OPS-001 第三条 | 同申请、材料类型、版本组合唯一；引用应属于当前申请 | F2 已有种子关联及版本唯一性校验；上传版控未实现 |
| R-08 | CC-REV-001 第一、二、九条 | 风控角色操作；状态前置条件和重复提交校验；完成至待审批、补件至待企业补充材料 | F2 已有演示角色及状态校验，非生产认证 |
| R-09 | CC-REV-001 第四、八条 | 逐项决定；修正须有理由；复核意见须填写 | F2 已检查上述基本条件；材料版本、政策和待办事项的结构化记录尚未实现 |
| R-10 | CC-REV-001 第五、九条 | 若经人工确认的关键缺口仍未解决，则阻止完成复核 | **新教学要求，F2 未实现**；缺口性质需人工确认，不能按关键词“证据不足”一律自动阻断 |
| R-11 | CC-REV-001 第六条 | 无报告、失败报告禁止直接完成复核 | F2 已实现无报告/失败报告限制；关键文件解析失败仍需结合真实解析链路 |
| R-12 | CC-OPS-001 第五条；CC-REV-001 第七条 | 比较材料/报告版本，保留报告引用快照；实质变更标记后要求重审 | F2 有关联引用和时间提示；实质变更判断、自动重审未实现 |
| R-13 | CC-OPS-001 第七条 | 产品、版本、状态和有效期过滤；冲突时停止作为确定依据 | 本地检索脚本已实现产品、教学状态过滤及语料快照校验；正式有效期、政策冲突判定和服务接口尚未接入，真实检索待验证 |
| R-14 | CC-POL-001 第十条；CC-REV-001 第一、九条 | 结构化预审输出不得携带最终授信决定，模型无写状态权限 | F2 模型禁额外字段；F3 服务仍需输出校验、工具权限控制及语义检查 |

核验意见是否充分、替代资料能否证明收入、用途是否得到解释、变更是否实质性，属于人工或受证据约束的辅助判断，不能仅用文件存在、字符串长度或模型自述“符合”判定。

本表条款均须与正文版本一致。正式接入前应为新清单、期间分支和状态门槛配置测试，给旧样例补齐独立的新测试数据；不得把原样例静默当作满足新规则。文件大小、页数、额度、利率、期限、贷款成数和差异容忍率没有本版规则，保持未配置并明确反馈。
