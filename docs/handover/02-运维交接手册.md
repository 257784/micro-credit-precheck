# 运维交接手册｜教学环境

本文面向维护本机教学环境的运维或开发人员。正式生产部署不在当前交接范围内；不得接入真实客户数据或将开发服务直接暴露到不可信网络。

## 服务、配置和入口

| 项目 | 当前入口或位置 | 运维关注点 |
|---|---|---|
| 前端 | `http://127.0.0.1:5173/`，Vite 开发服务 | `/api` 代理至后端；端口和配置见 README |
| 后端 | `http://127.0.0.1:8000/`，FastAPI | `/api/health` 是进程健康接口，`/docs` 是接口文档 |
| MySQL | `backend/.env` 中 `DATABASE_URL` | 启动时检查连接和 ORM 元数据对应的表存在；健康接口本身不做持续依赖探测 |
| 登录与账号 | 管理员页面；`scripts/create_local_user.py` | 密码为哈希存储；禁用账号或改角色可能撤销会话 |
| 原始材料 | 默认 `backend/.data/documents/`；可由 `CREDIT_DOCUMENT_ROOT` 指定 | 原件与数据库元数据共同构成业务数据；下载为未脱敏原件 |
| 知识库 | 教学语料 `docs/f3-knowledge-base/corpus/`，向量 `backend/.data/chroma/` | 检索依赖本地 BGE-M3 和匹配索引 |
| 模型 | `models/bge-m3/`；DeepSeek 配置在后端 `.env` | 模型与密钥不提交仓库；外部模型不可用要按降级处理 |

依赖安装、配置项、空库初始化和启动步骤以 [README](../../README.md) 为准。`.env` 中的真实凭据只由授权人员在本机维护；诊断和交接时不要输出、截图或传递密钥、Cookie、数据库 URL 明文。

## 日志与排查入口

- 管理员页面的“关键操作日志”及 `GET /api/operation-audit`：按申请查看操作者、动作、状态前后值、结果和固定原因码；普通业务用户无权查询。
- 管理员页面的“助手工具审计”及 `GET /api/credit-assistant/audit`：查看助手调用元数据。两类日志不是同一张表；字段与覆盖范围见 [关键操作日志说明](../architecture/33-关键操作日志.md)。
- 后端和前端开发服务的终端输出可用于定位启动和请求错误。项目目前没有配置统一的持久化应用日志、集中收集或日志轮转；不要假设这些设施存在。
- 业务操作日志覆盖指定动作；鉴权前失败、403、404、网络层失败等并非全部留痕。日志不保证防篡改，也不保存材料正文或人工意见。

## 常见故障处理

| 现象 | 先检查 | 处理与边界 |
|---|---|---|
| 页面打不开 | 前端进程、监听端口和本机访问地址 | 参照 README 启动前端；确认端口未被其他程序占用 |
| 页面有响应但接口失败 | 后端进程、`/api/health`、前端代理地址 | 健康接口返回正常只说明该路由可用，不证明 MySQL、模型和检索每次都正常 |
| 后端启动失败或报数据库不可用 | MySQL 服务、账号权限、连接配置、所需表 | 在本机核对配置但不输出凭据；已有库不要运行空库初始化脚本 |
| 登录失败 | 账号是否启用、角色、密码是否正确、Cookie 设置 | 本地 HTTP 不应开启 Secure Cookie；失败限流保存在单进程内存，重启会清空 |
| 材料解析失败 | 文件格式、是否为可提取文字的 PDF/DOCX、文件大小 | 不将解析失败当成无风险；扫描件需人工或 OCR |
| AI 报告失败或降级 | 预审结果状态、材料版本、外部模型配置与网络 | 保留失败状态并人工核验；不要将空结果当作无风险 |
| 政策问答或检索不可用 | 模型目录、Chroma 索引状态、语料版本、DeepSeek 配置 | 使用 README 中的模型文件检查和 `knowledge_base.py status`；检查后再决定是否重建索引 |
| 助手工具不可用 | 用户角色、申请归属、助手审计表、工具审计结果 | 审计不可用时工具会拒绝执行；不要关闭授权或审计来绕过问题 |
| 操作返回 409 | 当前申请状态、材料版本、最新报告和操作日志 | 提醒用户刷新，重新核验；不要手工修改状态来跳过业务流程 |

## 备份、恢复与交接

当前项目**没有自动备份、恢复演练或数据保留策略**。正式安排备份前，应明确负责人、频率、保存期限、访问权限、恢复时间目标和恢复验证方式。

1. 备份范围至少考虑 MySQL 业务、身份和审计表；上传文件目录；教学语料、配置模板、模型版本和重建索引所需信息。`.env` 和任何备份都可能包含敏感信息，应由授权人员单独安全保存，不放入源码仓库。
2. 上传文件与数据库元数据必须保持一致。进行一致性备份前应安排维护窗口并停止写入，避免数据库记录与文件版本不一致；具体数据库备份工具和权限由环境负责人确定。
3. 恢复先在**独立环境和独立数据库**演练：确认目标、恢复数据库及相应原件，核对申请、材料版本、账号权限和审计记录，再验证服务和业务流程。不得使用开发库或现有业务库直接试恢复。
4. Chroma 索引可能依赖语料和模型指纹；恢复时可先检查索引状态，如需重建应依据 README 并记录操作。不要把重建向量索引视为数据库或上传原件的备份。
5. 当前 `init_empty_database.py` 只用于全新空库，不是数据库恢复或迁移工具；其拒绝已有表或视图。数据库 DDL 可能隐式提交，失败可能留下部分表。

这些是交接建议，**本轮没有执行真实备份或恢复演练**。密码不可从哈希还原；需要重置时通过授权的账号管理流程进行，避免泄露或误撤销其他用户会话。

- 记录部署版本、责任人、服务地址、数据库和文件存储的位置、模型和索引版本、备份位置及最后一次演练时间；这些信息应保存在受控渠道，而不是包含密码的公开文档。
